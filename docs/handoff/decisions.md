### D1 App 框架：Flutter

- **选择**：Flutter 3.38.7（Dart 3.10.7），界面一套代码。
- **备选**：SwiftUI + Objective-C++ 桥接（最初的计划，见 README 旧版和 `ios/ui-design` 分支）；React Native；Kotlin Multiplatform / Compose Multiplatform；.NET MAUI。
- **理由**：
  1. 开发期间**没有 Mac**。SwiftUI 没有 Mac 连编译都做不到；Flutter 可以在 Windows/WSL 上以 Linux 桌面版完整运行同一套界面和**真实的**核心库，写测试、截图、标定，全部在现有机器上完成。
  2. 一套代码以后还能出 Android（Windows 上已有 Android SDK），覆盖不用 iPhone 的买家。
  3. `dart:ffi` 直接调用 C API，不需要额外的桥接层（RN 需要原生模块，MAUI/KMP 的 iOS 静态 C++ 库集成更繁琐）。
  4. 组件测试/集成测试框架成熟，能在没有设备的情况下覆盖整个流程（55 + 3 个测试）。
- **代价**：App 体积比原生大（Flutter 引擎约 10–20 MB）；界面是“仿 iOS”而非系统原生控件；后台任务、内存警告需要少量原生代码（已写好说明）。
- **何时重新考虑**：iOS 上 Flutter + 静态 OCCT 集成遇到无法解决的问题；苹果审核因体积/体验拒绝；决定只做 iOS 且有长期 Mac 开发资源时，可以用 SwiftUI 重写界面（核心库和 C API 不受影响）。

### D2 调用方式：dart:ffi + 后台 isolate

- **选择**：`dart:ffi` 直接调用 `stl2stp.h`；`inspect` 用 `Isolate.run`，`convert` 用 `Isolate.spawn` + `SendPort` 消息；取消用一块原生 `Int32` 内存。
- **备选**：在 UI isolate 直接调用（会卡死界面）；平台通道（MethodChannel）+ 原生线程（每个平台写一遍原生代码）；`ffigen` 自动生成绑定。
- **理由**：转换可能持续几分钟，阻塞在 C 里的调用必须离开 UI 线程；isolate 之间只传简单 Map，没有共享 Dart 对象；C 的取消回调在工作 isolate 内执行，读一块共享内存即可，不需要消息往返（工作 isolate 阻塞在 FFI 里时收不到消息）。手写绑定只有 12 个函数，比引入 `ffigen` 简单。
- **何时重新考虑**：API 函数大量增加时改用 `ffigen`；需要并行转换多个文件时（核心库的全局锁本来就会把 OCCT 部分串行化）。

### D3 默认转换模式：ORIGINAL

- **选择**：默认 `STL2STP_MODE_ORIGINAL`，App 的“推荐”预设也是 ORIGINAL；SEWING 作为“更严格”。
- **备选**：默认 SEWING。
- **理由**：ORIGINAL 是原桌面版的算法，用户（尤其是用过电脑版的）得到的结果与电脑版一致；更快（SEWING 实测慢 20–25%）；`core/fixes` 之后对有问题的输入会自动改用 SEWING 并告警，所以默认 ORIGINAL 不再会写出无效实体。
- **何时重新考虑**：如果真实用户数据里“校验未通过/不封闭”比例很高，或 SolidWorks 测试发现 ORIGINAL 输出有兼容问题。

### D4 焊接默认开

- **选择**：`weld_vertices=1`，App 开关“合并重合顶点”默认开，并属于三个预设的一部分。
- **备选**：默认关（与电脑版逐字节一致）。
- **理由**：大量 STL 导出器会留下 float 级别的微小缝隙（UV 球极点等），不焊接时 ORIGINAL 只能输出开放 shell（“没有实体”），这是用户最可能遇到的失败。焊接只作用于开放边界顶点、不会产生退化三角形、容差是对角线的百万分之一，对正常闭合模型**没有任何改变**；实测耗时差异在噪声内。关掉即可回到电脑版行为。
- **何时重新考虑**：出现焊接把本应分开的特征（极细缝、贴合但分离的零件）合到一起的真实案例。

### D5 时间戳用 UTC

- **选择**：默认写当前 UTC（STEP `…Z`）；覆盖值按偏移换算到 UTC。
- **备选**：本地时间无时区（原版）；保留用户给的偏移。
- **理由**：STEP 的 `time_stamp` 是 ISO 8601，本地无时区的时间在跨时区交换时有歧义；IGES 的日期字段没有时区槽位，只能用一个约定，统一 UTC 最不容易出错；手机时区随用户移动，UTC 让同一文件在任何地方含义相同；两种格式用同一套换算，测试简单。
- **何时重新考虑**：用户明确要求文件里显示本地时间（可以只在 App 的界面上显示本地时间，文件里仍写 UTC）。

### D6 共面合并容差

- **选择**：角度 1e-4 rad；线性 `max(sewing_tolerance, 1e-6×对角线, 4×FLT_EPSILON×最大坐标)`；合并后无效就撤销。
- **备选**：原版（未设角度容差 → OCCT 默认 1e-12 rad）；更大的角度容差（如 1e-2）。
- **理由**：STL 坐标是 float32，斜放平面上的三角形法向在 1e-7 量级抖动，1e-12 rad 几乎什么都合不了；1e-4 rad（约 0.006°）远大于量化噪声、远小于任何有意的设计角度。线性容差覆盖远离原点时的 float32 精度。BRepCheck 前后对比保证不会因合并把有效实体变无效。实测斜放立方体 n=4/10 都合并成 6 个面且有效。
- **何时重新考虑**：用户希望把“几乎共面”的扫描网格也合并（需要更大容差，会改变几何）；或发现某类模型在 1e-4 下误合并。

### D7 内存预算：70% 警告 / 100% 拒绝

- **选择**：预计峰值 > 可用预算的 70% 提示（可继续），> 100% 拒绝（只能减面）；预算 = 系统报告的可用内存 × 0.8。
- **备选**：不预检，只靠系统内存警告；只警告不拒绝。
- **理由**：iOS 内存不够时会直接杀掉 App（用户看到闪退且没有任何说明）。模型系数来自 PC 实测的最大 RSS，有误差，所以 70% 留出余量；超过 100% 基本必然失败，与其让用户等几分钟再闪退，不如事先拒绝并给出能成功的减面比例。转换中仍保留系统内存警告时的安全取消。
- **何时重新考虑**：拿到真机实测数据后调整系数和阈值（见 [recipes.md R4](recipes.md#r4-重新标定估算和内存系数)）；如果用户抱怨误拒，可以把拒绝也改成“仍然转换（可能失败）”。

### D8 估算显示为范围

- **选择**：时间和大小都显示“约 a–b”，并注明“估算值，实际以设备为准”。
- **备选**：单一数字；不显示估算。
- **理由**：耗时受设备、负载、模型形状影响很大（同一台机器忙时慢 1.1–1.9 倍）；单一数字会让用户觉得“不准”。范围的上下限经测试保证覆盖所有标定数据点。大小估算比较准（±10%），时间范围较宽。
- **何时重新考虑**：有了手机实测数据后可以收窄范围；如果用户觉得范围太宽没有意义，可以只显示上限（“最多约 b 秒”）。

### D9 一次性买断“完整版”

- **选择**：一个 Non-Consumable 商品 `com.stl2stp.app.pro`；免费额度默认不限制（框架就绪，数值待定）。
- **备选**：订阅；按次付费（Consumable）；完全免费 + 广告；付费下载。
- **理由**：工具类、单机、无服务器成本，用户（闲鱼买家、学生、小作坊）对订阅反感；一次性买断实现最简单（不需要服务端），恢复购买由 StoreKit 处理。具体价格和免费额度属于商业决定，代码里不写死。
- **何时重新考虑**：如果加入需要服务器的功能（云转换、大模型代转）；或数据表明转化率太低。

### D10 文件信息默认留空，示例作者用“致知屋”

- **选择**：作者/单位/产品/描述默认全空；文档、测试和示例里统一用“致知屋”作中文示例作者。
- **备选**：原版硬编码（“VINCENT”等）；OCCT 默认（“Open CASCADE …”）；用系统用户名。
- **理由**：不往用户文件里写入任何他们没有输入的信息（隐私，也避免“这文件是什么软件生成的”这种暴露）；需要时用户自己填，或在设置里设默认值。“致知屋”是项目中性的示例名，测试里同时覆盖了中文的 `\X2\` 编码。
- **何时重新考虑**：如果商业上希望在文件里留下 App 名（可以作为可选项加到“产品”默认值，不建议默认开启）。

### D11 IGES 元数据只写 ASCII

- **选择**：非 ASCII 替换为 `?` 并返回 METADATA_CHANGED；App 预览页提示。
- **备选**：原样写 UTF-8 字节（旧实现）。
- **理由**：IGES 5.3 字符串是 ASCII、Hollerith 按字节计数，按字符计数的读取器遇到 UTF-8 会读错长度甚至崩溃（验证中发现）；OCCT 读纯中文 Start section 还会读成空。STEP 能无损写中文，需要中文的用户用 STEP。
- **何时重新考虑**：不太可能；除非某个主流 CAD 明确支持并需要 UTF-8 IGES。

### D12 OCCT 8.0.1，从源码编译；Linux 共享库、iOS 静态库

- **选择**：官方 V8.0.1 tag，只编 FoundationClasses / ModelingData / ModelingAlgorithms / DataExchange，关闭所有可视化、Tcl、FreeType 等；Linux 用共享库装在 `~/occt-install`，iOS 用静态库（`build_ios_core.sh`）。
- **备选**：发行版自带的 OCCT 7.x（Ubuntu 20.04 只有很旧的版本）；与原版相同的 7.x；8.1 开发版。
- **理由**：8.0.1 是写作时最新的正式版；iOS 必须自己编（静态）；Linux 和 iOS 用同一版本才能保证行为一致；gcc 9.4 编不了 8.0.1，所以用 gcc-10。
- **何时重新考虑**：OCCT 出了修复我们已知问题（彩色统计输出、回读朝向）的新版本时，按 [recipes.md R6](recipes.md#r6-升级-occt-或-flutter) 升级。

### D13 在 Linux 桌面（WSL）上开发和预览

- **选择**：Windows + WSL2 Ubuntu 20.04；App 在 WSLg 里以 Linux 桌面版运行；窗口 430×900 模拟手机。
- **备选**：Windows 桌面版（需要 Visual Studio C++ 工具链和 Windows 版 OCCT，都没有）；Android 模拟器（需要 NDK 交叉编译 OCCT）。
- **理由**：OCCT 和核心库已经在 WSL 里编好；Linux 桌面版直接加载 `.so`，转换是真实的；不需要在 Windows 上安装任何东西。
- **何时重新考虑**：拿到 Mac 后，日常开发可以直接用 iOS 模拟器 / macOS 桌面版。

### D14 仓库只在本地，历史已整理

- **选择**：本地 git，没有 remote；交接时拷目录或 `git bundle`。历史整理过一次（统一了早期提交的作者信息），旧 hash 失效。
- **理由**：项目尚未决定开源/托管方式；OCCT 的 LGPL 义务（如何提供源码）也会影响托管选择。
- **何时重新考虑**：需要多人协作或备份时，选一个私有托管（注意不要把 `reference/` 原版源码推上去，`.gitignore` 已排除）。
