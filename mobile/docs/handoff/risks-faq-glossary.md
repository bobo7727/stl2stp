## 2. 风险与限制

- **几何本质**：输出是“由很多小平面组成的实体”，不能还原成圆柱、圆角等参数化特征，不能在 CAD 里改尺寸（只能做布尔、切割、测量等）。这是所有 STL→STEP 工具的共同限制，必须在商品描述里讲清楚（见 FAQ）。
- **大模型**：STEP 每个三角形约 2.4 KB，10 万三角形 ≈ 250 MB 文件、80 s、2 GB 内存（PC 实测）。手机上可能更慢、内存更紧。App 有 20 万面警告和 200 万面上限，以及内存预检。
- **手机性能未知**：所有时间和内存数据都来自 PC（12 核 WSL）；手机上没有测过。
- **OCCT 静态链接的 LGPL 义务**：见 §4，是上架前必须解决的问题。
- **单人维护的知识集中**：本交接文档就是为降低这个风险；所有构建步骤都可以照文档复现。
- **远端与离线备份**：当前源码在 GitHub master；本机尚未推送的工作仍可能丢失。可定期 `git bundle create … --all` 备份全部本地分支到别处。
- **苹果审核**：工具类 App 一般没问题；注意购买页不能有“价格待定”这类占位文字，隐私问卷选“不收集数据”。

## 3. 性能范围（面数 vs 时间、大小、内存）

PC 实测（WSL2 Ubuntu 20.04，Release，单次运行，输出到 D:；含 STEP 回读校验）。时间/大小来自 `app/tool/calib/calib.csv`（即 [flutter-app.md §7](../flutter-app.md#7-预计用时和大小估算与校准)），峰值内存来自 `app/tool/calib/memtime.csv`（`os.wait4` 的 `ru_maxrss`，另一次运行）：

| 三角形数 | 模型 | STEP 原版 | STEP 合并共面 | STEP 缝合 | IGES | 峰值内存（ORIGINAL STEP） |
|---|---|---|---|---|---|---|
| 5k | 球 | 3.3 s / 11.9 MB | 4.1 s / 7.7 MB | 3.9 s / 12.5 MB | 1.7 s / 10.1 MB | 140 MB |
| 20k | 球 | 14.1 s / 49.1 MB | 16.9 s / 31.7 MB | 17.0 s / 51.4 MB | 6.5 s / 41.1 MB | 437 MB |
| 20k | 方块 | 13.8 s / 44.6 MB | 5.4 s / **16 KB** | 17.0 s / 47.4 MB | 6.1 s / 34.5 MB | 未测 |
| 50k | 球 | 37.1 s / 124 MB | 44.3 s / 79.4 MB | 46.3 s / 130 MB | 18.1 s / 102 MB | 1016 MB |
| 100k | 球 | 82.0 s / 255 MB | 95.4 s / 164 MB | — | 34.7 s / 207 MB | 2017 MB（102k） |
| 100k | 方块 | 79.1 s / 227 MB | 28.1 s / 16 KB | 99.3 s / 241 MB | 33.5 s / 170 MB | 1901 MB（合并共面 1526 MB） |

经验公式：STEP ≈ 0.33 ms/面 + 0.18 s/MB 校验 ≈ **0.7–0.8 ms/三角形**；文件 ≈ **2.4 KB/三角形**；内存 ≈ **50 MB + 20 kB/三角形**（合并共面约 16 kB/三角形，减面 50% 后约 10–11 kB/输入三角形）。减面 50% 大约让时间、大小减半。手机建议：≤ 5 万三角形直接转；5–20 万建议减面；> 20 万 App 会提示。

## 5. 闲鱼买家常见问题（Support FAQ）

可以直接用作客服回复模板（App 内帮助页的 FAQ 也有对应内容）。

**为什么在 SolidWorks 里打开是一堆曲面 / 很多小三角形，不能改尺寸？**
STL 本身就只是三角形网格，没有“圆柱”“圆角”这些特征信息。转换后的 STEP 是由这些三角形组成的实体，可以测量、切割、做布尔运算、加特征，但不能像原始模型那样改尺寸。如果导出的是 IGES，它本来就是曲面格式，需要在 CAD 里“缝合”成实体；要实体请选 STEP。

**为什么完成页说“模型不封闭，已按曲面导出”？**
STL 有破洞（常见于扫描模型或导出出错的文件）。可以先在建模软件里修补，或者在 App 里选“更严格”方式再转一次；确认高级设置里“合并重合顶点”是打开的。

**为什么文件这么大？**
STEP 是文本格式，每个三角形面要写几十行，大约每个三角形 2.4 KB，10 万个三角形就是 200 多 MB。办法：打开“合并共面”（平面多的零件效果非常明显，一个方块可以从 45 MB 变成 16 KB）；或者“减少面数”（减到 50% 文件约减半）；或选“文件更小”预设。

**选哪种方式？**
- 一般零件：“推荐”（和电脑版一样，最快）。
- 文件太大、细节要求不高：“文件更小”。
- 一个文件里有好几个零件、或者校验没通过：“更严格”。

**STEP 和 IGES 选哪个？**
优先 STEP（打开就是实体，中文文件信息不会丢）。只有对方软件只认 IGES 时才选 IGES。

**转换很慢或者中途退出？**
面数很多时手机算得慢、内存也可能不够。App 会提前提醒；建议减少面数后再转，转换时保持 App 在前台。

**IGES 里写的中文作者名不见了？**
IGES 格式只支持英文字符，中文会被换成“?”。需要中文请导出 STEP。

**尺寸单位是什么？**
STL 不记录单位，App 按文件里的数字原样写入（CAD 里按毫米解释）。如果打开后大了或小了 1000 倍或 25.4 倍，说明原 STL 是用米或英寸导出的，在 CAD 里缩放即可。

**文件会上传吗？**
不会，所有处理都在手机本地完成。

**怎么传到电脑？**
完成页点“分享…”，发到微信“文件传输助手”、QQ“我的电脑”，或用隔空投送、邮件；也可以“存到‘文件’”后用 iCloud 同步。

## 6. 术语表

| 术语 | 解释 |
|---|---|
| **STL** | 3D 打印最常用的格式，只记录一堆三角形（每个三角形 3 个顶点 + 法向），没有单位、颜色、特征。分 ASCII（文本）和二进制两种 |
| **STEP**（.step/.stp，ISO 10303） | CAD 之间交换实体模型的标准格式（文本）。本项目写 AP214 协议。能表示实体、壳、面、边、点的完整拓扑 |
| **IGES**（.igs/.iges） | 较老的 CAD 交换格式（1980 年代，最新 5.3），主要传曲面；不同软件对实体的支持不一致 |
| **B-rep**（边界表示） | CAD 内核表示实体的方式：实体由封闭的壳（shell）包围，壳由面（face）组成，面由边（edge）围成，边由顶点（vertex）连接；每个面有几何（如平面）和朝向 |
| **solid / shell / face / edge / vertex** | 实体 / 壳 / 面 / 边 / 顶点。封闭的壳才能构成实体；开放的壳只是曲面 |
| **流形（manifold）** | 每条边恰好被两个面共用的网格/实体；有边被 3 个以上面共用叫非流形，CAD 一般无法处理 |
| **朝向 / 绕序** | 三角形顶点的顺序决定法向朝外还是朝内；所有面朝向一致才能定义“里面”和“外面” |
| **缝合（sewing）** | 把相邻、但各自独立的面在容差范围内合并共享边，形成连续的壳（OCCT `BRepBuilderAPI_Sewing`） |
| **焊接（weld）** | 把坐标几乎相同的顶点当作同一个点 |
| **共面合并** | 把在同一平面上的相邻三角形合成一个多边形面（OCCT `ShapeUpgrade_UnifySameDomain`） |
| **QEM**（二次误差度量） | 经典的网格简化算法（Garland & Heckbert 1997）：每次折叠一条边，选误差最小的，直到达到目标面数 |
| **OCCT**（Open CASCADE Technology） | 开源 CAD 内核（C++），提供 B-rep 建模和 STEP/IGES 读写；FreeCAD 也基于它 |
| **Parasolid** | 西门子的商业 CAD 内核，SolidWorks、NX、Solid Edge、Onshape 使用 |
| **healing** | 读取 CAD 文件时自动修复小问题（如边的容差、面的朝向） |
| **BRepCheck / BOP 检查** | OCCT 的形状有效性检查 / 布尔运算前的自相交等检查 |
| **Hollerith 字符串** | IGES 的字符串写法：`长度H内容`，如 `3HABC` |
| **`\X2\…\X0\`** | STEP 文件里表示 Unicode 字符的转义（UTF-16 十六进制） |
| **FFI / isolate** | Dart 调用 C 函数的机制 / Dart 的独立线程（不共享内存，靠消息通信） |
| **ULP** | 浮点数相邻两个可表示值的间距；float32 在 100 附近约 7.6e-6 |
